📋 Detalhamento das Subtasks

5. CHECKPOINT — 24h de estabilidade

Propósito: Validar que o sistema manteve estabilidade por 24h consecutivas antes de liberar a Fase 1.


Critérios:
  • Zero execuções failed do supervisor em 24h
  • Zero agentes offline ou blocked
  • Zero falhas críticas do DORA refresh

Uso: 
python3 scripts/checkpoint_24h.py

Saída: .workdev/checkpoint-24h.json

1.1 Worktree por task

Propósito: Isolar execução de cada task em worktree separado.


Funcionalidades:
  • Cria worktree em .workdev/worktrees/task-{id}
  • Branch separado: task/{id}
  • Estado persistido em .task-state.json
  • Instruções de limpeza ao final

Uso: 
./scripts/create_task_worktree.sh <task-id> [agente]

1.2 Bloquear commit de agente em develop

Propósito: Prevenir que commits de agentes modifiquem diretamente a branch develop.


Padrões bloqueados:
  • feat(agents):
  • fix(agents):
  • chore(agents):
  • refactor(agents):
  • test(agents):
  • docs(agents):

Instalação: 
cp scripts/hooks/pre-commit-agents .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit

1.3 Portão de testes antes da revisão

Propósito: Garantir que toda task passe por validação automática antes de revisão humana.


Checks executados:
  • pytest: Testes Python (apps/api)
  • vitest: Testes TypeScript (opcional)
  • linting: ruff + eslint
  • typecheck: mypy + tsc

Uso: 
python3 scripts/validate_task_for_review.py <task-id>

Retorno: 0 (aprovado) ou 1 (reprovado)

9. PILOTO — task real ponta a ponta

Propósito: Orquestrar todo o fluxo da Fase 1 em uma única execução.


Etapas:
  1. Validar pré-requisitos (git, python3)
  2. Criar worktree para task
  3. Instalar hook de bloqueio
  4. Executar portão de testes
  5. Executar checkpoint de 24h
  6. Consolidar resultado

Uso: 
./scripts/piloto_task_ponta_a_ponta.sh [task-id] [agente]

Estado: .workdev/piloto-state.json
