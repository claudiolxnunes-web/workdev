## Achados de seguranca

- **Runbook mandava root executar codigo gravavel pelo `workdev`.**
  `sh scripts/deploy/workdev-deployctl` (dono `workdev`) rodado como root = escalada

- **Workspace expoe o repo ao navegador:** lista vem do git (nao do disco) +

  bloqueado por conter conteudo arbitrario. `.env.example` e afins nao aparecem porque
  estao ignorados.

## Armadilhas (e como evitar)

- **Gate de deploy builda com a arvore de trabalho, nao com o commit.** O `prepare`
  empacota `git archive HEAD`, mas o `pnpm build` do gate roda no checkout: mudanca
  nao commitada de outro agente (ex.: troca de rota no `App.tsx`) iria para producao
  no bundle. Quando houver trabalho alheio na arvore: `git stash push -u -- <arquivos>`,
  `prepare`, `stash pop` (conferir com o diff salvo antes). O `deploy.sh` tambem recusa
  arvore suja ("arvore de trabalho nao esta limpa").
- **`dist/` buildado como root quebra o gate** (`emptyDir` do Vite, EACCES). Buildar
  como `workdev`.
- **Arquivos `.bak` soltos bloqueiam o deploy** (arvore suja). Backup vai para fora do
  repo ou para `.workdev/archives/`, nunca ao lado do arquivo.
- **Prova de deploy vence em 15 min.** `approve` e `deploy` precisam vir logo apos o
  `prepare`; `deploy.sh` sem approval falha com `No such file ... approvals/<id>.json`.
- **pnpm com store em `/root`**: `pnpm add` como `workdev` pede reinstalacao. Store
  agora e do `workdev`; ver decisao de ownership.
- **`$` em JSON escrito por shell vira expansao**: a licao do escalonamento saiu com
  `"USbash,0002"` (o `$0` virou `bash`). Escrever JSON por Python/Write, nao por
  heredoc sem aspas.
- **`git rm`/`rm -r` podem ser negados pelo ambiente do agente**: passar o comando ao
  operador em vez de contornar.
